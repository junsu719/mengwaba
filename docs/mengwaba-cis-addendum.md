## 0. 改版範圍:全站三個工具,不是只有垃圾車(v2 新增)

| 工具 | 路徑 | 狀態 | 頁面產生方式 |
|---|---|---|---|
| 垃圾車 | `/trash/` | 上線,四城市 | 首頁、城市索引、行政區頁為**建置時靜態**;清運點頁為**即時讀 D1** |
| 行事曆/連假 | `/calendar/` | 2026-09-04 上線,約 24 頁 | 全靜態 |
| 農民曆 | `/lunar/` | 上線 | 靜態(「今日」內容於瀏覽器端計算) |

品牌定位為**台灣生活資訊整合網站**,垃圾車只是其中一個工具。原規格的「各工具專屬輔助色」必須為上表三個工具各自指定。

## A. 垃圾車工具:設計必須涵蓋四個城市,不是只有高雄

原規格的範例網址是高雄頁面,但本站有四個城市、**四種不同的資料形狀**:

| 城市 | depart(離站時間) | 星期 | 特殊 |
|---|---|---|---|
| 高雄 | 有(`21:24~21:27`) | 完整 | — |
| 台中 | 有 | 完整 | 有**沿街收運**(措辭不同,不是「停靠」而是「經過」) |
| 桃園 | **一律無** | **約 70% 未知** | 需顯示免責說明 |
| 新北 | **一律無** | 完整 | **有廚餘班表**(第三種收運類型) |

因此:

1. **Hero 的時間顯示不可寫死成 `21:24 ~ 21:27` 區間格式。** 沒有 depart 時只顯示單一到站時間(現有措辭:「約 21:24 抵達」)。**嚴禁用 arrive + N 分鐘推算出一個 depart。**
2. **週表(§19)的七天 ● / — 呈現,在星期未知的點必須整個不渲染**,改顯示現有的免責說明:
   > 本站僅取得此清運點的到點時間,未取得收運星期。完整班表請以桃園市環境管理處「垃圾清運路線即時查詢系統」為準。
3. **新北的廚餘區塊(`foodscraps_schedule`)必須納入設計**,比照資源回收區塊,用 `hasFoodscraps` 判斷是否渲染。原規格完全沒提到這塊。
4. **純資源回收點**(無一般垃圾班次)不可顯示「今天沒有收運」——那是錯誤結論。沿用現有分支措辭。
5. **台中沿街收運**的措辭邏輯(`isPassThrough`)不可被重寫覆蓋。

**驗收要求**:設計完成後,四個城市各至少實際渲染 3 頁檢查,並涵蓋:有/無 depart、星期已知/未知、有/無資源回收、有/無廚餘、沿街/定點、純回收點。

## B. 「距離現在約 XX 分鐘」與所有「今天/現在」內容的實作限制

原規格 §17/§18 提到倒數,並警告不要做錯誤的時間計算。技術上必須:

1. **一律前端計算(client-side JS)**。清運點頁經 Cloudflare 邊緣快取,伺服器端算出的倒數對看到快取版本的使用者是錯的。
2. **時區強制 `Asia/Taipei`**,不可依賴執行環境時區(Workers 在資料中心)。
3. **僅在該點的星期與時間皆已知時顯示**。桃園星期未知的點**不得顯示倒數**——不知道今天收不收,就無從倒數。
4. JS 失效時不可留下空白或 `NaN`,預設不渲染該區塊。
5. **(v2 新增)靜態頁會把時間凍結在建置當天。** 行政區頁、行事曆、農民曆都是建置時產生,任何「今天」「現在」「下次」相關的內容若在伺服器端計算,會永遠停在 build 那一天。新增到這些頁面的時間相關元件**一律前端計算**。
6. **(v2 新增)共用同一套時間邏輯。** 行事曆的「下次放假倒數」、農民曆的「今日」內容已是前端 + `Asia/Taipei`,改版時應整併成同一個元件或工具函式,不可改回伺服器端,也不可各寫一套。

## C. 不得刪除既有 SEO 與功能內容(內容退化是最大風險)

2026-08-09 已上線的垃圾車行政區頁強化內容,**必須全部保留**,只可重新排版,不可為了視覺清爽刪除:

- 里別索引(含錨點跳轉)
- 依里別分組的清運點列表
- 星期分佈總覽
- 時段分佈
- 資源回收 / 廚餘覆蓋率
- 資料驅動 FAQ
- 資料來源與更新日期
- 站內連結(同縣市其他行政區、城市索引)
- 清運點頁的「鄰近清運點」連結(Googlebot 靠這些連結發現清運點頁,數量維持 5 個)

行事曆與農民曆的必保留內容,見 §K、§L。

另外:

- **全站所有頁面(含 `/calendar/`、`/lunar/`)的 `title` 與 `meta description` 不可改動**,除非先跟 Jun 確認。垃圾車頁的版本是依 GSC 真實查詢字優化過的(包含「時間表」這類用字),改動會直接影響排名與點閱率。
- **品牌名不可放在 title 最前面**。使用者搜的是「仁武垃圾車時間表」,不是品牌名。

## D. 資料來源標註是授權義務,不是裝飾

以下資料皆依「政府資料開放授權條款第 1 版」提供,**該條款要求標示出處**。資料來源區塊與更新日期(垃圾車為 `fetched_at`)**不得因版面調整而移除或縮到看不見**:

- 垃圾車:四個城市各自的來源機關
- 行事曆:行政院人事行政總處(資料集 14718)
- 農民曆:頁面上現有的來源與驗證說明,原樣保留

## E. 效能:字型是最大風險

原規格 §27 要求 Performance > Visual effects,但 §5 指定 Noto Sans TC ——完整字重檔案極大,直接載入會嚴重傷害 LCP。必須:

- 字型子集化(只含實際用到的字),或
- 使用 `font-display: swap` + 系統字型 fallback,或
- 評估直接用系統中文字型堆疊

**部署前後各量一次 Lighthouse 分數,不得低於現況。**(農民曆頁的生僻字較多,子集化時須確認神明名稱等用字沒有缺字。)

## F. 改版本身不得新增任何網址

原規格 §26 已說不改網址,v2 修正如下:

- **改版不得新增頁面**(包含分類頁、路名頁、任何「即將推出」的工具頁)。
- **已上線的工具可以、也應該被連結**:首頁的行事曆卡片連到 `/calendar/`,農民曆卡片連到 `/lunar/`。
- **尚未建立的工具**,首頁的「即將推出」卡片**只能是無連結的視覺元素**,不可連到任何實際頁面。
- 全站搜尋若後端尚未支援,**只做 UI 不做假功能**(原規格 §25 已載明)。
- 理由(2026-08-31 更新):GSC 顯示新城市的行政區頁 Google 有來爬、但拒絕收錄,瓶頸是網域信任度,不是頁面數量不夠。為改版多開頁面不會幫助收錄,只會稀釋。

## G. 保留既有的 404 頁

站上現在有**兩種**客製 404(2026-08-26 起):

1. **全站 404**:標題「找不到這個頁面」+ 搜尋框 + 四縣市索引,處理打錯的網址、不存在的城市或行政區。
2. **清運點 404**:清運點不存在時,附該行政區清運點列表連結。

**兩者都必須保留功能與 HTTP 404 狀態碼**,僅可套用新視覺。

## H. 吉祥物:以文字規格為準,不以示意圖為準

附圖的首頁示意出現大面積卡通青蛙,與原規格 §6「不要可愛幼兒園風格」、§7「極簡、幾何、小尺寸、不要大面積卡通插畫」互相矛盾。**以文字規格為準**,蛙蛙僅出現在 loading / empty / error / 資料更新等小尺寸情境。

## I. 驗證與上線流程(沿用既有鐵律)

1. **(v2 修正)** 現有測試是**組合矩陣斷言測試**(`content.test.ts`、`calendar.test.ts` 等),不是 snapshot 檔;最近一次紀錄為 94 個,**以當下 `npm test` 實際數字為準**。改動若使測試失敗,**不可盲目修改斷言讓它通過** —— 必須先確認新輸出正確、並由 Jun 讀過才更新。
2. 組合矩陣重跑:四城市 × 各資料形狀,加上行事曆兩個年度、農民曆,實際輸出字串貼給 Jun 讀過。
3. `npm run build` 通過。
4. commit → **`wrangler versions upload`** 產生版本專屬預覽 → 回報預覽網址,**停下等 Jun 人工抽看** → 經 Jun 明確同意才 `wrangler versions deploy`。workers.dev 與正式站是同一個版本,**不是測試環境**。
5. **(v2 新增)回滾版本 ID 一律從 `wrangler deployments list` 取目前 100% 流量的那個**,不可從 `wrangler versions list` 取(後者包含從未上線的預覽版本)。
6. **`wrangler d1` 指令一律在 `site/` 目錄執行**(repo 根目錄的 `.env` 會讓 wrangler 誤用無 D1 權限的 token)。
7. **(v2 新增)** 行政區頁是建置時靜態產生,驗收時要確認行政區頁**確實是新版視覺**,不是舊版殘留。

## J. 分階段執行,不要一次做完

建議順序(每階段回報再往下):

1. **Phase 1 Audit**(原規格 §35)—— 只讀不改,回報現有架構與風險,**範圍含三個工具**
2. **Phase 2 Design Tokens** —— 純 CSS 變數,零風險
3. **Phase 3 Core Components** —— 元件庫,尚未套用(含 §B-6 的共用時間元件)
4. **Phase 4 首頁** —— 首頁不是流量來源,風險最低,可先驗證整套視覺
5. **Phase 5 行事曆 + 農民曆** —— 全靜態、資料形狀單純,風險中低;但它們是負責爭取外部連結的工具,§K、§L 必須逐條驗
6. **Phase 6 垃圾車行政區頁 + 清運點頁** —— **風險最高,四城市邊界情況全部要驗**
7. **Phase 7 Responsive QA + Lighthouse + D1 用量複查(§M)**

**Phase 4 之後先停下讓 Jun 看過,再進 Phase 5。**

## K. 行事曆工具的必保留項目(v2 新增)

1. **請假攻略計算器必須在 `/calendar/` 首頁明顯可見**。這是與商周、KKday 等文章型競品唯一的差異點,不可為版面簡潔收到下一層。
2. **「下次放假」倒數**保留,依 §B 前端計算。
3. **2027 頁的「媒體說 9 個、本站算出 8 個」說明**保留,不可刪除或縮成小字——少了它,從其他網站來的人會以為本站算錯。
4. **年度描述一律由當年資料計算**。端午/中秋/教師節在 2026 有連假、2027 沒有,元件與設計稿中不可寫死任何跨年份的描述句。
5. **行事曆檔案「下載優先、訂閱次要」的層級不可倒過來**;請假攻略「先講要請幾天、再講可連休幾天」的寫法保留。
6. 非官方聲明與「實際休假依公司規定」的提醒保留。

## L. 農民曆工具的必保留項目(v2 新增)

1. **宜忌警語必須緊貼宜忌區塊**,不可移到頁尾、折疊或縮到看不見。
2. 「今日」內容維持瀏覽器端計算(§B)。
3. **網址已定案,上線後不改**:`/lunar/`、`/lunar/deity/{slug}/`、`/lunar/birthday-convert/`。
4. 改版不擴充功能:**不新增擇日、吉日、運勢等入口或按鈕**,也不為尚未收錄的神明做佔位頁。
5. 視覺沿用全站 CIS,不另做一套紅金傳統風格,維持同一品牌的一致感。

## M. D1 用量:改版不得增加資料庫讀取(v2 新增)

2026-08-31 起 Cloudflare 對免費額度強制執行,目前用量約 46.7%,幾乎全部來自清運點頁。

1. **改版不得新增任何 D1 查詢**。首頁、城市索引、行政區頁、行事曆、農民曆維持**零 D1 讀取**。
2. 新元件若需要資料(例如首頁的統計數字、工具卡片資訊),**一律使用建置時產生的靜態資料**,不可每次請求去查 D1。
3. 清運點頁不得因改版增加額外查詢。
4. 部署後隔至少 6 小時,用 `wrangler d1 insights` 確認每日讀取量**不高於改版前**。
